# 虚拟化与集群组件升级关注点（面试要点）

与 VM Operator 落地环境强相关：k3s/K8s、KubeVirt、CDI、CNI、存储。升级时强调**矩阵兼容**与**回滚策略**。

## 1. KubeVirt 与 CDI

- **版本矩阵**：KubeVirt 与 Kubernetes 小版本通常有官方支持表；升级集群前确认目标 KubeVirt 版本。
- **行为变化**：API 字段、默认设备模型、迁移与热插拔能力可能随版本调整；CRD 变更需读 Release Notes。
- **验证**：在 staging 用代表性 Wukong（多网、多块盘、CloudInit）跑一轮创建/删除/重启。

## 2. CNI（Multus 等）与网络策略

- **Multus**：与主 CNI、NMState（若使用）版本组合需验证；升级后重点看 **NetworkAttachmentDefinition** 与 Pod 多网卡是否仍符合预期。
- **趋势知识（面试）**：部分团队评估 **Cilium** 多网或 eBPF 路径；可答「选型取决于运维成熟度、内核版本、与现有 NMState/Multus 的替换成本」。

## 3. 存储（Longhorn 等）

- **CSI 与数据面**：存储驱动升级往往涉及卷挂载行为、扩容与快照语义；与 CDI DataVolume 创建路径一起测。
- **话术**：「存储升级优先保证**已有卷可挂载**，再测**新卷创建**。」

## 4. 发行版（k3s / 上游 K8s）

- **k3s**：关注 embedded 组件版本、默认 Admission、API Server 参数；与上游差异可在面试中简述「边缘/单机交付选 k3s，大规模多租户可能选标准发行版」。
- **回滚**：备份 etcd（或 k3s 数据目录策略）、保留旧版 Helm chart 与镜像 tag。

## 5. 小结（可背诵）

升级顺序常见实践：**先升级集群与平台 Operator（KubeVirt/CDI/CNI/存储），再升级业务 Operator**；全程用**代表业务 CR** 做冒烟，并保留**指标与日志**对照升级前后。
